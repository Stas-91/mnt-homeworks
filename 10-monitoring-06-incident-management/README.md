# Постмортем: Сбой GitHub — 21 октября 2018

## Описание инцидента
21 октября 2018 года GitHub столкнулся с 24-часовым сбоем, затронувшим операции Git, вебхуки и API-запросы. Причиной стала сетевая ошибка во время обслуживания базы данных, приведшая к несогласованности данных между регионами.

## Хронология
- **Начало**: 21 октября 2018, 22:52 UTC
- **Окончание**: 22 октября 2018, 23:07 UTC
- **Продолжительность**: ~24 часа
- **Воздействие**: Частичная или полная недоступность сервисов GitHub, повлиявшая на пользователей по всему миру.

## Причина
Плановое обслуживание базы данных вызвало сетевой раздел между дата-центрами. Это привело к рассинхронизации основного кластера MySQL с его репликами, что вызвало несогласованность данных. Системы оркестрации не справились с переключением, усугубив проблему.

## Действия по устранению
1. **Немедленные**: Инженеры остановили автоматическое переключение, чтобы предотвратить дальнейшую несогласованность.
2. **Восстановление**: Вручную восстановили согласованность данных, перестроив реплики из резервных копий и синхронизировав данные.
3. **Коммуникация**: Регулярные обновления статуса публиковались на странице статуса GitHub и в социальных сетях.

## Уроки
- **Мониторинг**: Улучшить обнаружение сетевых разделов и проблем синхронизации баз данных.
- **Устойчивость**: Переработать оркестрацию для обработки частичных сбоев без каскадных эффектов.
- **Тестирование**: Проводить тесты хаос-инжиниринга для симуляции сетевых разделов.

## План действий
1. Внедрить продвинутые инструменты мониторинга сети к 1-му кварталу 2019.
2. Переработать механизмы переключения для устойчивости к 2-му кварталу 2019.
3. Запланировать регулярные учения по восстановлению после сбой

## Вывод
Сбой выявил уязвимости в инфраструктуре баз данных и сети GitHub. Улучшение мониторинга, устойчивых систем переключения и тестирования поможет предотвратить подобные инциденты и повысить доступность для пользователей.
